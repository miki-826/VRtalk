# 環境認識・歩行・ロボキャラクター（2026-10-24）

キャラクターが部屋の家具を把握し、Jevの判断または待機中の気まぐれで部屋を歩きます。無料（CC0）の3Dモデルを使った3人目のキャラクター「ロボ · 好奇心」を追加しました。既存の「しろ」「こはく」は元のWhiteChibiのままで、同じく歩けます。

## 言葉で説明した場所・床の指さし・テレポート（2026-11-14 追加）

ユーザー指示「言葉で説明した場所に移動するように。言葉で話した内容をAIが何でもやるように」。

- `MotionStep.place`（`MotionPlace`: front / behind / left / right / beside / between / center / corner / far_side / pointed）を `walk_to` に追加。端末内パーサー（`LocalMotionParser.Described`）とAIプランナー（スキーマ・指示文）の両方が使う。
- `App/Core/PlaceResolver.cs` が場所を床の空きセルへ変換する。物の前後左右は**ユーザーから見た向き**（前＝ユーザー側、後ろ＝向こう側）。`target` が `user` ならユーザー自身の前後左右（既定1m）。`between` は2つの物の向かい合う端の中点。`corner` は壁から0.9m内側の四隅（物の指定があればそれに近い隅）、`far_side` はユーザーから見て部屋の反対側。`amount` は物の端からの距離（m）。
- 目標に最も近い空きセルを選び、ユーザーの足元（0.55m以内）には立たない。1.2m以内に立てる場所がなければ失敗として理由を伝える（例: 壁に付いたソファの後ろ）。
- `pointed`（「あそこ」「そこ」「指さしたところ」、指さし直後の「ここ」）は `CharacterBrain.IndicatedSpot()`: 12秒以内に指さした床 → なければ視線（頭の向き）が床に当たる点 → 物を見ていればその物のそば。指さした床は、到着した時点（または物を指さした時点）で忘れる。「あそこのソファ」のように物の名前があれば、その物が優先。
- `far_side` はユーザーが部屋の中央付近（中心から1m以内）にいるときは向いている方向の壁際、それ以外は部屋の中心をはさんだ反対側。
- パーサーの区別: 「〜に／へ／まで」は行き先、「〜から」は出発点（行き先にしない）、「〜で＋動作」は「そこへ行ってから動作」。「くるっと回って」「90度回って」は回転、「後ろに回って」はユーザーの後ろへ回り込む、「右に回って」は向きを変える。部屋にない物の前後左右（「壁の前に立って」）は端末内では理解不能として扱い、AIプランナーへ渡す（黙って別の動きにしない）。
- 床のレイ判定（`RayHit`）で遮るのは床に立っている家具とおもちゃだけ。窓・カーテン・壁の棚・吊り照明・ラグは遮らない。レイの始点が家具の範囲内にある場合もその家具は無視する。
- 「動きを止める」（`MotionPerformer.Stop`）は実行中の計画を忘れ（`Last = null`）、`Version` を進める。AIの続き（`ContinueAgent`）や、考え中だった古い計画（`Instruct` / `ProcessInputAsync`）は、止めた後に動き出さない。
- 指さし: 右グリップ／Fキーの「意図的な指さし」は、レイが最初に当たるもので決まる（`SceneAwareness.RayHit` / `FloorPoint`）。物ならその物へ（従来どおり）、床なら `UserBodyTracker.PointingSpot` に記録して `CharacterBrain.GoToPointedSpot()` がその場所へ歩かせる。腕を伸ばして0.8秒静止する自動検出は物だけが対象（床は誤検出が多いため）。
- 行き先の輪（`App/XR/FloorMarker.cs`）は歩行中だけ表示。UIパネルにレイが当たっている間は、指さし・テレポートとも無効。
- 時間帯: `MotionAction.set_time`（「夜にして」「明るくして」）。`CharacterBrain.TimeRequested` を `AppRoot` が設定に反映する。
- 接続なしの指示: `CharacterBrain.Instruct(text)`（「動きを試す」→「言葉で指示する」）。端末内パーサー → 分からない部分はOpenAIキーがあればAIプランナー → 続きが必要なら既存のエージェントループ。
- プレイヤーの移動: `XRPointerInput.Teleport`（右スティック前倒し→離す／Tキー）。操作を離した時だけ移動し、照準中にレイがUIパネルに乗る・トラッキングが一瞬切れる・文字入力を開く、では移動しない。`SceneAwareness.CanStand`（壁から0.5m・家具の外）かつキャラクターから0.5m以上の床だけ。スティック／WASD歩行は `CanUserStep` で壁・家具・キャラクターに当たると止まり、軸ごとに滑る。以前はキャラクターの0.5m以内に入ると離れる方向にも動けなかったのを修正。
- テスト: EditMode `PlaceTests.cs`・`LocalMotionParserTests.cs`（初版はCodex作成、Claudeが確認・追加）、PlayMode `PlaceInstructionTests.cs`。Antigravity（Gemini）の読み取り専用レビューで見つかった不具合（テレポートの誤発動、停止後の再開、「〜から」の逆方向、回転指示の横取り、「あそこのソファ」、窓による床指定の遮断、部屋の奥の向き、指さし地点の残留など）は修正し、回帰テストを追加した。
- 未対応（端末内パーサー）: 「ソファの向かって右」「私と並んで立って」、まだ出していないおもちゃの前後左右（「ボールを出してボールの後ろに行って」）。OpenAIキーがあればAIプランナーが扱う。

## 環境認識（`App/Core/SceneAwareness.cs`）

- 部屋の読み込み時にシーンを走査し、オブジェクト名から日本語ラベル（ソファ・窓・暖炉・ベッド・椅子・テーブル・本棚・カウンター・植物など）を付ける。窓の外の木・照明・粒子は対象外。
- 接している同じ種類の部品（窓ガラスと桟、暖炉の石と炎など）は1つにまとめ、同種が複数あれば「椅子1」「椅子2」のように番号を付ける。Botanicaのように見た目が統合メッシュの部屋は、名前付きの当たり判定（BoxCollider）から読み取る。
- 床の範囲と、床に置かれた家具から0.2m格子の歩行可能マップ（`NavGrid`）を作る。家具はキャラクターの半径0.28m分ふくらませ、壁際0.35mは歩かない。
- キャラクター視点の説明文を作る。例: 「部屋: 暖炉のリビング（広さ約8m×7m）。あなたから見た配置: テーブル(左1.5m)、ソファ(左後ろ2.3m)、暖炉(後ろ2.3m)…。ユーザーは正面2.4mにいます。ユーザーは本2の方を見ています。」
- 説明文は Live 接続直後と移動の到着時に「参考情報（命令ではない）」としてGPT-Live-1へ送る。Jevには毎回 `perception.surroundings / userLookingAt / nearbyObject / walking` として渡す。

## 歩行（`App/Character/CharacterLocomotion.cs`）

- 8方向A*で経路を求め、見通しの良い点を間引いて直線的に歩く。ユーザーの立ち位置（半径0.45m）を避ける。2秒進めなければ中止。
- 向きを合わせてから歩き出し、到着後は目的の物の方を向いて約6秒眺め、その後ユーザーへ向き直る。ユーザーが視界から大きく外れると、その場で向きを変える。
- しろ・こはく（アニメーション無しのWhiteChibi）は脚・膝・腕を手続き的に振って歩く。ロボはモデル付属の Walking クリップを速度でブレンドする。

## Jevの判断

`movement`（stay / approach_user / give_space / go_to_object / wander）と `target`（部屋のオブジェクトID または none）の2問を追加。targetは部屋に実在するIDだけを受け付け、存在しない物への移動はstayに戻す。movementが無い古い形式の応答はstayとして扱う。

- ユーザーの発話ごと: 感情・ジェスチャー・視線と合わせて移動を決定。歩き出すと「〇〇へ歩いています…」と表示し、Liveへも移動内容を伝える。
- 接続中の知覚イベント（距離・注視の変化、30秒の沈黙）: 同様に移動を決めることがある。
- Jevを使わない時（未接続・Jev反応OFF）: 25〜45秒ごとに、近くの物を見に行く／部屋を少し歩く／遠いユーザーへ近づく。端末内だけで動き、API通信はしない。設定 > 身体の反応 > 「部屋の中を歩き回る」でOFFにできる。

## 細かな行動とユーザーの動き（2026-10-24 追加）

Jevの質問をさらに4つ追加（未指定なら既定値）。

|質問|選択肢|効果|
|---|---|---|
|pace|normal / slow / hurry|歩く速さ×0.6〜1.7。足取り・歩行アニメの速さも連動|
|approach|direct / around|aroundは直線の脇の空いた点を経由して弧を描いて近づく|
|arrival|none / sit / crouch_look / point|到着後に座る（椅子・ソファ・ひじ掛け椅子・ベッドのみ、約25秒）、しゃがんで見る（約6秒）、指さす（約4秒）。行き先の物が必要|
|walking|continue / stop / turn_to_user / change_destination|歩行中だけ有効。立ち止まる・振り返る・行き先を変える|

- 歩行中はJevへ3秒ごとに問い合わせる（trigger `walking`）。通常の知覚反応は8秒以上の間隔のまま。
- ユーザーの動き（`App/XR/UserBodyTracker.cs`）: 手を肩より上で左右に3回振る＝wave、腕を伸ばして同じ物へ0.8秒向ける＝point、頭の高さが立った時の72%未満に0.4秒＝crouch、85%超へ戻る＝stand_up。検出するとLiveへ事実を伝え、Jevへ即時（最短2.5秒間隔）に `user_gesture:*` で問い合わせる。Jevの知覚には `userGesture / userPointingAt / userCrouching / walkingTo` を含める。
- Jevが使えない時の端末内ルール: 手を振る→手を振り返して向き直る、指さす→急いでその物へ行きしゃがんで見る、しゃがむ→遠ければゆっくり近づき、近ければ一緒にしゃがむ、立つ→立ち上がる。待機中の散歩でも速さ・弧・座る・しゃがむ・指さすをランダムに混ぜる。
- 姿勢は `BodySystem.Pose`（stand/sit/crouch/point）。WhiteChibiは脚・膝を折り、ロボは脚が短いため腰を少し下げて前傾する。指さしは上腕→前腕の向きを対象へ回転。
- PC版の代用キー: H 手を振る、F マウスの先を指さす、C しゃがむ/立つ（視点の高さを変え、同じ検出ロジックで判定）。
- 未確認: Questのハンドトラッキング・コントローラーでの実際の検出精度（しきい値は実機で調整が必要）。

## ロボ · 好奇心（`Editor/RobotCharacterBuilder.cs`）

- モデル: three.js examples の RobotExpressive（Tomás Laulhé / Quaternius作、CC0 1.0）。`tools/convert-robot.py`（Blender 5.2）でglbをFBXへ変換。ボーンに親子付けされた部品を100%ウェイトのスキンメッシュへ付け替え、余分な球体を除去。
- アニメーション14種のうち Idle / Walking を常時ブレンド。手振り→Wave、うなずき→Yes、肩すくめ→No、笑い→Jump。首振り・視線は手続きで上書き。
- 表情: 付属モーフ Surprised / Sad を感情に対応（excited→驚き85、curious→驚き40、sad→悲しみ90、concerned→悲しみ50 など）。口のモーフがないため、発話中は頭を小さく揺らす。
- 再生成: メニュー `Quest AI > Add robot character (free CC0 model)`。確認画像付きは `QuestAI.Editor.RobotCharacterBuilder.BuildAndReview`（`artifacts/previews/Robot-*.png`、ログに各部屋の認識結果 `ROOM_AWARENESS`）。

## PC版の操作追加

部屋の中ではWASDまたは矢印キーで視点が床の上を移動します（右ドラッグの向き基準、壁から0.5m・キャラクターから0.5m以内には入らない）。キャラクターは距離の変化に反応します。

## 制約

- 物の認識はシーン内のオブジェクト名による。カメラ映像の画像認識ではなく、Quest本体の現実の部屋（MR）も対象外。
- 段差・家具の上には乗らない。椅子に座る動作はない（ロボの Sitting クリップは未使用）。
- Jev実接続での移動判断、Quest実機での歩行の見え方・72Hz負荷は未確認。
