# Jevの利用と状態表示

JevBehaviorProviderは https://api.typesafe.ai/v1/systemone へBearer認証付きPOSTを送り、Choice応答を検証して行動へ変換する。接続テストもこの実リクエストを使用する。

通常の自動Jev判断は「Jev利用設定ON」かつGPT-Live接続中に、会話入力・距離や視線の変化・歩行中・ユーザーのしぐさをきっかけに行う。毎フレームAPIを呼ぶ処理ではない。Jev接続テストはLive接続とは独立して実行できる。

キー不要の動作は、瞬き・呼吸・視線追従、ローカル散歩、Live未接続時のしぐさへのルール反応、言葉での場所指定・動きの指示（端末内で理解できる範囲）、おもちゃ遊び。これらが動くことはJevの認証成功を意味しない。

画面下部のJev表示:
- キー未設定: API未使用。
- キー保存済み・未検証: 保存されているだけ。認証成功ではない。
- API応答待ち: リクエスト処理中。
- 有効なAPI応答を受信: HTTP成功に加え、行動データの検証に通った。この起動中・現在のキーとモデルでの受信回数を表示する。常時接続を意味しない。
- 失敗: 認証・通信・不正応答など。以前の成功表示を残さない。
- 通信中止: キャンセルされた操作を成功にしない。

キーやモデルを変更すると検証状態をリセットし、古い設定で開始した応答は破棄する。再起動後も未検証から始まる。Windows/Questのキーは暗号化して保存されるため、以前の入力が引き継がれる。完全に未設定で試す場合は設定のPrivacyからAPIキーを削除する（OpenAIのキーも削除される）。

実APIの認証成功を今回の自動テストで確認したわけではない。テストではキーなし・401・不正応答・成功・設定変更・キャンセルをテスト用プロバイダーで再現する。
